## 1. نبذة عن المشروع (Project Overview)

مشروع **Mini ERP Stock & Sales** هو نظام إدارة مخزون ومبيعات متكامل مصمم خصيصاً للمؤسسات التجارية الصغيرة والمتوسطة، تم بناؤه وفق أعلى معايير الجودة والأمان وهندسة البرمجيات. 

- **إطار العمل الأساسي:** CodeIgniter 3.1.13 معتمد على معمارية MVC الصارمة وممتد بخدمات الأعمال (Business Services).
- **لغة البرمجة وبيئة التشغيل:** PHP متوافق تماماً مع PHP 7.4+ ومختبر على بيئة PHP 8.2.12 تحت بيئة Windows + XAMPP.
- **قاعدة البيانات:** MySQL / MariaDB 10.4.32 باستخدام محرك التخزين التبادلي الآمن `InnoDB` وترميز الحروف الموحد `utf8mb4_unicode_ci`.
- **الواجهة الأمامية وتجربة المستخدم:** واجهات ويب عربية كاملة الاتجاه (RTL) مبنية على HTML5, CSS3, JavaScript, jQuery, وتقنيات AJAX غير المتزامنة ومكونات Bootstrap المتناسقة، مع شعار وهوية بصرية متكاملة وأيقونة مفضلة (Favicon).
- **العملة الرسمية المعتمدة:** الريال السعودي (SAR).
- **نوع الكميات:** أعداد صحيحة حصراً (Integers Only)، مع منع تام للأرصدة السالبة تحت أي ظرف.

## 3. البنية المعمارية وهندسة الكود (MVC + Services Architecture)

يلتزم المشروع بمعمارية نظيفة ثلاثية الطبقات تضمن فصل الاهتمامات وقابلية الصيانة والتوسع:

1. **طبقة المتحكمات (Controllers):**
   - ترث من `MY_Controller`، وتتميز بكونها نحيفة (Thin Controllers).
   - مسؤولة حصرياً عن استقبال طلبات HTTP، التحقق الأولي من تدفق الطلب، فحص المصادقة والصلاحيات عبر الجلسات، واستدعاء النماذج والخدمات وإرجاع واجهات العرض أو استجابات JSON المنظمة.
   - لا تحتوي المتحكمات على أي استعلامات SQL مباشرة أو حسابات مالية مركبة.

2. **طبقة الخدمات ومكتبات الأعمال (Business Services & Libraries):**
   - مركزية للعمليات الحسابية والمنطق التجاري المتكرر مثل `Audit_service`.
   - توحيد معالجة العمليات وضمان عدم تكرار الشيفرة البرمجية بين وحدات النظام المختلفة.

3. **طبقة النماذج والبيانات (Models Layer):**
   - مسؤولة بالكامل عن التفاعل مع قاعدة البيانات عبر `CodeIgniter Query Builder` حصراً ومستندة إلى معاملات ذرية متكاملة (`trans_begin()`, `trans_commit()`, `trans_rollback()`).
   - تطبيق خوارزميات التزامن والحماية من التسابق باستخدام أقفال القراءة الحصرية `SELECT ... FOR UPDATE`.
   - تنفيذ الحسابات المالية والتحقق الحسابي الدقيق مع تقريب النصف للأعلى `PHP_ROUND_HALF_UP`.

4. **طبقة واجهات العرض (Views Layer):**
   - مسؤولة حصراً عن العرض والتقديم ولا تحوي أي منطق تجاري أو استعلامات بيانات.
   - واجهات متناسقة باللغة العربية مع دعم كامل لاتجاه RTL، مكونات ترقيم مشتركة (`pagination.php`)، ورسائل فلاش تفاعلية.

## 4. نموذج الصلاحيات والأدوار (Role-Based Access Control - RBAC)

يحتوي النظام على ثلاثة أدوار صارمة ومحددة بدقة؛ يتم فحص وتطبيق الصلاحيات حصراً على مستوى الخادم (Server-Side) مع عدم الاعتماد نهائياً على إخفاء الأزرار في الواجهة كأداة حماية:

```
                  ┌─────────────────────────────────────────┐
                  │          المستخدم في النظام             │
                  └────────────────────┬────────────────────┘
                                       │
         ┌─────────────────────────────┼─────────────────────────────┐
         ▼                             ▼                             ▼
   ┌───────────┐                 ┌───────────┐                 ┌───────────┐
   │   Admin   │                 │ Warehouse │                 │   Sales   │
   │   (مدير)  │                 │ (مستودع)  │                 │  (مبيعات) │
   └─────┬─────┘                 └─────┬─────┘                 └─────┬─────┘
         │                             │                             │
 ┌───────┴───────┐             ┌───────┴───────┐             ┌───────┴───────┐
 │- وصول شامل    │             │- محصور في     │             │- محصور في     │
 │- إدارة النظام │             │  المستودعات   │             │  المستودعات   │
 │- إلغاء الفواتير│             │  المعينة له   │             │  المعينة له   │
 │- سجل التدقيق  │             │- توريد وتسوية │             │- إنشاء فواتير │
 │- كل التقارير  │             │  المخزون فقط  │             │- تقرير مبيعاته│
 └───────────────┘             │- حظر المبيعات │             │- حظر التوريد  │
                               │  والفواتير    │             │  والإلغاء     │
                               └───────────────┘             └───────────────┘
```

- **المدير (`admin`):** يملك الصلاحية الكاملة لإدارة كافة أقسام النظام، إضافة المستخدمين وتعيين المستودعات، التوريد والتسوية، إنشاء وإلغاء الفواتير، الاطلاع على سجل التدقيق، واستعراض كافة التقارير التشغيلية والمالية.
- **أمين المستودع (`warehouse`):** محصور بالكامل في نطاق المستودعات المعينة له؛ يملك صلاحيات توريد وتسوية المخزون والاطلاع على أرصدة وحركات المخزون والمخزون المنخفض؛ ومحظور تماماً من إدارة العملاء، إنشاء أو إلغاء فواتير المبيعات، التقارير المالية، أو سجل التدقيق.
- **مسؤول المبيعات (`sales`):** محصور بالكامل في نطاق المستودعات المعينة له؛ يملك صلاحيات إدارة العملاء وتفعيلهم، وإنشاء فواتير المبيعات، واستعراض فواتيره ومبيعاته هو فقط؛ ومحظور تماماً من توريد المخزون أو تسويته، إلغاء الفواتير، إدارة المستخدمين، أو سجل التدقيق.

## 5. إدارة المخزون وحركاته الذرية (Inventory & Atomic Ledger)

تُدار حركة المخزون في النظام كدفتر أستاذ تاريخي غير قابل للحذف أو التعديل (Append-Only Immutable Ledger):
1. **استقلالية الأرصدة:** يُدار المخزون بصورة مستقلة لكل منتج داخل كل مستودع في جدول `warehouse_stock`.
2. **منع الأرصدة السالبة:** يُمنع نزول رصيد أي منتج عن الصفر منعاً باتاً؛ ويتم التحقق من كفاية الرصيد قبل الخصم، بالإضافة إلى فحص الرصيد الفعلي عبر أقفال `FOR UPDATE`.
3. **التوثيق الإلزامي للحركات:** كل عملية تغيير في المخزون يُسجل لها فوراً سجل تاريخي في `stock_movements` بنوع الحركة (`in`, `adjustment`, `sale`, `sale_reversal`)، قيمة التغير (Delta)، الرصيد السابق، والرصيد اللاحق.
4. **توازن الحركة الحسابي:** يتحقق النظام دائماً من المعادلة الرياضية الصارمة: `After Quantity = Before Quantity + Delta`.
5. **إلزامية سبب التسوية:** تتطلب حركة التسوية (`adjustment`) سبباً واضحاً لا يقل طوله عن 5 أحرف ولا يتجاوز 255 حرفاً.
6. **مفتاح منع التكرار (Idempotency Key):** تزويد حركات المخزون بمفتاح فريد من 32 حرفاً لمنع تكرار العملية عند إعادة إرسال الطلب بالخطأ.

## 6. دورة حياة فواتير المبيعات (Sales Invoices Lifecycle)

تخضع فواتير المبيعات لدورة حياة مالية ومخزنية متكاملة ومحكمة:
1. **التحقق من العميل والمستودع:** التحقق من أن العميل نشط (`is_active = 1`)، وأن المستودع نشط، ومصرح لمسؤول المبيعات بالبيع منه.
2. **حساب المبالغ على السيرفر حصراً:** لا يثق النظام بأي إجماليات أو حسابات واردة من المتصفح؛ يتم جلب سعر البيع المعتمد للمنتج من قاعدة البيانات، واحتساب إجمالي البند، المجموع الفرعي، الخصم، والإجمالي النهائي في السيرفر باستخدام العملة الرسمية `SAR`.
3. **خصم المخزون الذري:** يتم قفل أرصدة المنتجات المعنية والتأكد من كفايتها ثم خصمها وتسجيل حركات مخزون من نوع `sale` بكميات سالبة في نفس المعاملة.
4. **الترقيم التسلسلي التلقائي:** توليد رقم الفاتورة بصيغة قياسية فريدة يومياً: `INV-YYYYMMDD-XXXX` بالاعتماد على جدول `invoice_sequences` مع قفل الصف لمنع التكرار بين العمليات المتزامنة.
5. **التقاط اللقطة التاريخية (Snapshots):** يتم تسجيل كود المنتج (SKU) واسم المنتج وسعر الوحدة المباع به ضمن جدول البنود `sales_invoice_items` كلقطة تاريخية غير قابلة للتغيير حتى لو تم تعديل سعر المنتج أو اسمه لاحقاً في بطاقة الصنف.

## 7. إلغاء الفواتير والحركات العكسية (F08 Invoice Cancellation)

تتبع عملية إلغاء الفواتير ضوابط رقابية ومحاسبية صارمة:
1. **الإلغاء ليس حذفاً (Cancellation is NOT Deletion):** يُمنع حذف الفاتورة أو بنودها أو حركات البيع المرتبطة بها؛ بل تظل السجلات التاريخية محفوظة بالكامل.
2. **حصر الإلغاء بالمدير:** الإلغاء متاح حصرياً للمدير `admin` وفقط للفواتير التي لا تزال بحالة نشطة (`active`).
3. **توثيق بيانات الإلغاء:** تحديث حالة الفاتورة إلى `cancelled` وتوثيق تاريخ ووقت الإلغاء `cancelled_at`، المستخدم المنفذ `cancelled_by`، وسبب الإلغاء الإلزامي `cancellation_reason` (بين 5 و 255 حرفاً).
4. **استعادة المخزون بحركات عكسية:** إنشاء حركات مخزون عكسية من نوع `sale_reversal` بكميات موجبة (+Delta) لإعادة الكميات إلى المستودع، مع ربط كل حركة عكسية بحركة البيع الأصلية المناظرة عبر حقل `reversal_of_movement_id`.
5. **منع الإلغاء المزدوج وحماية التزامن:** قفل الفاتورة بـ `SELECT ... FOR UPDATE` والتحقق من عدم إلغائها مسبقاً، ورفض أي محاولة لاحقة برمز خطأ `ALREADY_CANCELLED`؛ مما يحول دون استعادة المخزون مرتين في حالات التزامن أو الضغط المزدوج على الزر.

### معايير التصدير والتوافق الإقليمي مع Excel:
- **معالجة فاصل القوائم الإقليمي (Regional Delimiter Fix):** نظراً لأن إعدادات Windows الإقليمية للمملكة العربية السعودية واللغة العربية (`ar-SA`) تعتمد الفاصل المنقوط (`;`) كفاصل قياسي للقوائم، تم ضبط التصدير الافتراضي ليعتمد الفاصل المنقوط مع دعم المعامل `?delimiter=comma` للفاصلة العادية؛ مما يضمن فتح الملف مباشرة في Microsoft Excel في أعمدة منفصلة ومنظمة بدقة دون الحاجة لأي تحويل يدوي.
- **دعم النصوص العربية (UTF-8 BOM):** تصدير الملفات ببادئة بايتات الترتيب الموحد `\xEF\xBB\xBF` لضمان قراءة الحروف العربية دون تشويه.
- **حماية التصدير من الحقن (CSV Formula Injection):** تحييد الرموز الخطرة (`=`, `+`, `-`, `@`) في بداية الخلايا النصية ببادئة علامة الاقتباس الأحادية لمنع تنفيذ أكواد خبيثة في برنامج Excel، مع الحفاظ على الأرقام السالبة الحقيقية بصيغتها العددية القياسية.

## 9. سجل التدقيق المركزي (F10 Central Audit Logs)

يوفر سجل التدقيق رقابة شاملة وغير قابلة للتلاعب على كافة الأحداث الحيوية في النظام:
1. **جدول `audit_logs`:** مُنشأ بمحرك `InnoDB` وترميز `utf8mb4_unicode_ci`، ومفهرس بفهارس مركبة للبحث والفرز السريع.
2. **الحفاظ على التاريخ عند حذف/تعطيل المستخدمين:** حقل `user_id` مرتبط بالمستخدمين بقيد `ON DELETE SET NULL` لضمان بقاء السجل التدريبي سارياً ومقروءاً حتى لو تم حذف المستخدم لاحقاً.
3. **تطهير البيانات الحساسة (Metadata Sanitization):** تستبعد دالة `sanitize_metadata()` تلقائياً كلمات المرور وتجزئتها (`password_hash`) ورموز الجلسات ورموز CSRF لضمان عدم تسريب أي أسرار تقنية في سجل التدقيق.
4. **التكامل الذري الإلزامي (Atomic Rollback Guarantee):** دمج تسجيل التدقيق داخل المعاملات التبادلية لحركات المخزون وفواتير المبيعات؛ وفي حال فشل تسجيل التدقيق أو حدوث أي استثناء، تتراجع المعاملة بالكامل وتُلغى كافة التأثيرات على المخزون والفواتير لحماية اتساق البيانات.
5. **واجهة إدارية للقراءة فقط (Read-Only Admin Viewer):** واجهة `/audit_logs` مقصورة حصرياً على المدير، تتيح استعراض وتصفية السجلات ومطالعة البيانات الوصفية بتنسيق JSON منسق، دون وجود أي أدوات لتعديل أو حذف السجلات نهائياً.

## 11. الأمان والحماية التقنية (Security Implementation)

يطبق النظام سياسات دفاعية متعددة الطبقات (Defense in Depth):
1. **الوقاية من هجمات XSS:** استخدام دالة الهروب المعيارية `html_escape()` لجميع المخرجات الديناميكية في واجهات العرض دون استثناء.
2. **الحماية من هجمات تزوير الطلبات عبر المواقع (CSRF):** تفعيل حماية CodeIgniter CSRF الصارمة على مستوى التطبيق بالكامل مع إعادة تجديد الرموز واستخدام دالة `form_open()` وربط الرموز مع كافة طلبات AJAX.
3. **الحماية من حقن أوامر SQL (SQL Injection):** استخدام `Query Builder` حصراً مع تمرير المعاملات المجهزة (Parameterized Queries) والتحقق الإلزامي من الأنواع العددية.
4. **تشفير كلمات المرور:** استخدام خوارزمية BCRYPT القياسية عبر `password_hash()` و `password_verify()` مع منع تخزين أي كلمات مرور بنص صريح.
5. **التحقق من صحة المدخلات على السيرفر (Server-Side Validation):** التحقق الصارم من صحة الأرقام، الكميات، الأسعار، التواريخ، وحالات السجلات قبل تمريرها لقاعدة البيانات.
6. **الحماية من حقن معادلات CSV (Formula Injection):** تحييد الرموز الحسابية التي تبدأ بها الخلايا النصية لمنع تشغيل أكواد برمجية في Excel.
7. **إلغاء تنشيط المستخدمين والحسابات المعطلة:** رفض تسجيل الدخول فوراً للمستخدم المعطل (`is_active = 0`) وحظر وصوله لكافة الوظائف.

## 12. قواعد البيانات والنزاهة المرجعية (Database Integrity & Constraints)

تتميز قاعدة بيانات المشروع بهيكلية هندسية متينة:
- **محرك التخزين الموحد:** كافة الجداول (12 جدولاً) تستخدم محرك التخزين التبادلي `InnoDB` حصراً لدعم المعاملات التبادلية والقيود المرجعية.
- **الترميز والترتيب:** موحد على مستوى قاعدة البيانات وكافة الجداول: `utf8mb4` مع الترتيب `utf8mb4_unicode_ci` لدعم اللغة العربية والرموز التعبيرية والخاصة بدقة متناهية.
- **المفاتيح الخارجية (Foreign Keys):** تطابق دقيق في أنواع البيانات والمحارف (Unsigned Integers)، مع تعريف واضح لإجراءات الحذف والتحديث (`ON DELETE RESTRICT` للبيانات التاريخية و `ON DELETE SET NULL` لسجلات التدقيق).
- **الفهارس المخصصة (Compound Indexes):** إضافة فهارس مدروسة على أعمدة البحث الشائعة (مثل `sku`، `invoice_number`، `entity_type + entity_id`، `warehouse_id + product_id`) لضمان سرعة الاستعلام واستجابة النظام حتى مع نمو حجم البيانات.
